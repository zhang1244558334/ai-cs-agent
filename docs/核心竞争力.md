# AI 智能客服系统 — 核心优势（5 点）

> 对比市面上大厂 SaaS 客服（阿里小蜜、网易智企等）和开源方案（Rasa 等）

---

## 1. 快慢分离架构，成本极低

**市面上多数方案：** 所有问题都走大模型，token 消耗大，每次对话都要花钱。

**本项目：** 三级路由（关键词→正则→LLM），80% 的常见问题在毫秒级通过规则匹配搞定，**0 元调用费**。只有剩下的 20% 才调大模型。同等对话量下，API 成本是大厂方案的五分之一到十分之一。

## 2. 本地可部署，不依赖第三方 API

**市面上多数方案：** 必须接入厂商的 SaaS 服务，数据上传到第三方服务器，断网即停服。

**本项目：** 架构设计支持随时切换本地模型（Ollama + Qwen2.5），改三行配置即可。断网也能跑，数据不出本机。这对数据敏感的中小商家、教育机构、政企客户是刚需。

## 3. 规则与 AI 分层，不滥用大模型

**市面上多数方案：** 议价、路由、分类全交给大模型，效果不稳定且成本不可控。

**本项目：** 议价用参数化公式算出来的（动态温度梯度让步），路由用关键词/正则匹配，只有真正需要理解能力的场景才调大模型。**核心逻辑是确定的，不确定的部分交给 AI。** 这比全盘依赖 AI 的方案更可靠、更可控。

## 4. 一人可维护，改话术不改代码

**市面上多数方案：** 改客服话术、调议价策略需要等程序员发版，迭代周期长。

**本项目：** 所有业务规则配置化（router_rules.yaml / bargain.yaml），客服话术全在 prompt 文件里。改一句"回复要客气"不用改代码，重启即生效。个人开发者或业务人员都能维护。

## 5. Bot Gateway 策略模式，天生多平台通用

**市面上多数方案：** 接入新平台需要重新开发，不同厂商的适配器互不兼容。

**本项目：** 接入层抽象了 `IBotPlatform` 接口，新增一个平台只需写一个 adapter（约 50 行代码），核心路由、Agent、RAG 逻辑一行不改。今天接 Web，明天接淘宝/闲鱼/企微，业务代码零改动。

---

## 一句话总结

> **用大厂的架构思路（快慢分离、规则兜底、插件化接入），用个人开发者能承受的成本（本地部署、按需调 API、一人维护），做出了一个可独立部署的、不依赖任何第三方的 AI 客服系统。**
